# Постобработка OCR паспорта РФ

Решение тестового задания: проверяю результаты OCR, восстанавливаю поля по MRZ и
справочнику и выбираю, принимать документ или запрашивать повторный снимок.
Все решения принимаю локально на CPU. Дату проверки фиксирую: **01.10.2026**.

## Подход

Сначала выполняю проверяемые исправления текста, сверку MRZ и контрольных цифр,
проверку форматов, геометрии строк и срока замены паспорта. Затем оцениваю надёжность
полей через sklearn Pipeline. В исследовании сравниваю логистическую регрессию,
случайный лес и градиентный бустинг, подбираю параметры и пороги.

По умолчанию использую `strict`: девять лесов с раздельной калибровкой,
принимаю документ только при единогласии. Это осторожный режим под исходный
приоритет нуля ошибочных принятий. Его ограничение - **низкий охват**.

## Результаты

Внутренняя групповая CV на 3000 документах; повтор одного паспорта не разделяю
между обучением и проверкой. Для strict три разбиения дают 27, 15 и 19 принятий
без наблюдаемых FP. Число схем выбираю по этим же проверкам, поэтому независимым
подтверждением нулевого риска их не считаю.

| Режим | Принято на основном OOF | FP | FN | Стоимость |
|---|---:|---:|---:|---:|
| strict | 27 (0.9%) | 0 | 1883 | Зависит от цены отказа |
| cost5 | 1809 (60.3%) | 36 | 137 | 317 |
| cost10 | 1782 (59.4%) | 30 | 158 | 458 |
| cost25 | 1710 (57.0%) | 25 | 225 | 850 |

В условии точного отношения стоимости ошибок нет. **5×, 10× и 25× задаю как допущения**:
FP - принятие неправильного ответа, FN - отказ от уже правильно восстановленного
документа с допустимыми датами. Принимаю `C_FN=1`, минимизирую `k*FP+FN` и использую
эту стоимость для выбора модели, гиперпараметров и порога внутри calibration.
Экономические варианты допускают FP и не выполняют буквальное требование нуля ошибок.

`answers.jsonl` содержит 2000 ответов test, из них **22 accept** в режиме strict.
Разметки test нет. Наиболее вероятный прогноз числа ошибок - 0; ожидание около
0.76, прогнозный 95%-ный интервал 0-4 при переносимости риска внутри источников.
Ноль наблюдаемых FP на train не гарантирую для test.

## Запуск

Python 3.11+. Зависимости устанавливаю заранее; во время запуска интернет не нужен,
веса моделей и справочник уже включены в репозиторий.

```bash
python -m pip install -r requirements.txt
python postprocess.py data/test_predictions.jsonl answers.jsonl
```

Альтернативный сценарий с FP в 25 раз дороже FN:

```bash
python postprocess.py data/test_predictions.jsonl answers_cost25.jsonl --policy cost25
```

Также доступны `cost5` и `cost10`. Скрипт сохраняет порядок и ID, отклоняет повреждённые
метаданные и неизвестные источники, не читает train-разметку. Путь к справочнику и
весам определяет относительно скрипта, поэтому команда работает из другого каталога.

## Файлы и воспроизведение

- `solution.ipynb` - компактное исследование, сравнение моделей, экономика и ошибки.
- `postprocess.py`, `passport_ocr.py` - CLI и общая логика исследования и инференса.
- `train.py` - повторное обучение и групповая валидация.
- `artifacts/models.joblib`, `model_manifest.json` - веса, версии, пороги и хеши данных.
- `artifacts/*_oof.csv`, `cv_tuning.csv` - прогнозы CV и результаты внутреннего подбора.
- `answers.jsonl` - готовые ответы test в основном режиме.
- `report.pdf` - отчёт на двух страницах; `report.md` - текстовая версия.

```bash
python -m pip install -r requirements-dev.txt
python train.py --validate
python postprocess.py data/test_predictions.jsonl answers.jsonl
python -m unittest discover -s tests -v
python evaluate.py artifacts/oof_strict_answers.jsonl data/train_labels.jsonl
```

Ноутбук по умолчанию использует сохранённые результаты CV; для пересчёта переключаю
`RUN_VALIDATION=True`. Полный пересчёт занимает несколько минут CPU. Предоставленный
`evaluate.py` проверяет поля; даты проверяю дополнительно в своём коде.

## Ограничения и источник справочника

В 10 случаях VIZ и MRZ согласуются, а эталон отличается. Изображений в пакете нет,
поэтому не устанавливаю, где ошибка, и сохраняю эти случаи в метриках. Полную
юридическую действительность без реестра не подтверждаю: проверяю доступные даты
и возрастные сроки. Дизайн разрабатываю на выданном train, независимый test скрыт.
